# Публичный счётчик посетителей

Показывает уникальные IP за сегодня и за всё время в правом нижнем углу десктопа. Мобильные посещения учитываются, блок скрыт на телефонах и планшетах до 1024 px с сенсорным управлением. Использует цвета темы сайта и общий AnimatedNumber калькулятора. Подсчёт начинается с подключения: прошлые посещения не восстанавливаются.

Это оценка посещаемости, не число людей: NAT объединяет посетителей, VPN/динамические IP увеличивают счётчик. Считаются загрузки страниц с JavaScript; известные боты, DNT/GPC и заблокированные запросы не учитываются. Отсутствие cookie не делает этот показатель идентификацией людей.

## Архитектура

GitHub Pages остаётся статическим. Единственная функция /api/visitors размещается на существующем Vercel metal-site. Production на sortament.pro обращается к https://metal-site-five.vercel.app/api/visitors. Vercel собирает статический Next export и отдельную Node-функцию через static-build/node builders; npm run build для Pages не меняется. На preview каждый Origin имеет отдельное пространство Redis и пометку «тест»; только sortament.pro/www считаются боевыми.

Один фоновый POST после загрузки, приоритет low, таймаут 5 секунд, без аналитического SDK, cookies, fingerprint или постоянного polling. Страница, вернувшаяся из фона на следующий день, обновляет счётчик. День определяется в Asia/Novosibirsk. API берёт IP только из перезаписанного Vercel заголовка x-vercel-forwarded-for, нормализует IPv6 и записывает HMAC-SHA256. IP и ключи доступа не передаются в браузер и не логируются приложением. Инфраструктура провайдеров обрабатывает IP при обслуживании запросов.

Lua атомарно добавляет идентификатор в множества и получает SCARD: повторный IP не увеличивает счётчики, параллельные запросы не теряют посещения. Общий набор без срока хранения; дневной живёт 48 часов. Лимит 20 обращений на адрес в минуту. CORS допускает только сайт и собственные Vercel адреса. Это не защита от целевой накрутки: Origin вне браузера можно подделать, адреса через VPN менять. Для такого случая нужны ограничения на стороне Vercel Firewall.

При недоступности хранилища показываются «—» и «Статистика недоступна», а не нули или тестовые числа. Калькулятор работает независимо. Уже полученные числа сохраняются при ошибке.

## Подключение

1. В команде vladislav-s-projects6 принять условия Upstash человеком: https://vercel.com/vladislav-s-projects6/~/integrations/accept-terms/upstash?source=cli . CLI требует human acceptance.
2. Создать Upstash for Redis **Free**, имя sortament-visitors, регион iad1. **autoUpgrade=false**, **eviction=false**, prodPack=false. Подключить к metal-site для production/preview/development. Upstash внедрит KV_REST_API_URL/KV_REST_API_TOKEN либо UPSTASH_REDIS_REST_URL/UPSTASH_REDIS_REST_TOKEN.
3. Добавить серверный VISITOR_COUNTER_SECRET: случайные 32 байта (hex). Один неизменный секрет во всех окружениях; смена секрета меняет идентификаторы и раздует total. Никогда не использовать NEXT_PUBLIC_ для секретов.
4. Повторно развернуть preview. Проверить два POST с одного адреса, другой адрес, смену дня, отказ базы и отдельные пространства preview/production. Затем пользователь проверяет preview и подтверждает merge main.
5. После merge проверить Production на Vercel и sortament.pro. Настроить правила Firewall/лимиты по фактической нагрузке.

Free ограничен 250 МБ и 500K команд в месяц по текущему тарифу Upstash; один визит выполняет несколько Redis-команд внутри Lua. Это не 500K посещений. При исчерпании лимита бесплатная база может перестать принимать запросы. Платный переход запрещён без отдельного решения владельца. Vercel имеет собственные лимиты Functions и текущий план команды нужно проверить отдельно. Счётчик не гарантирует бесплатность при любой нагрузке.

Источники: https://upstash.com/pricing/redis ; https://upstash.com/docs/redis/features/restapi ; https://vercel.com/docs/headers/request-headers ; https://vercel.com/docs/project-configuration/vercel-json .
